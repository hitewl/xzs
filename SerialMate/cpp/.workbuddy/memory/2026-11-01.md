## 修复：IME 输入导致"敲的命令不上串口"（backspace 删不掉 / Enter 不执行）
- 根因：中文输入法（即使英文/半角模式）向 RichEdit 送字走 `WM_IME_CHAR` 而非 `WM_CHAR`。
  `ViewProc` 只拦了 `WM_CHAR`/`WM_KEYDOWN`，IME 字符被 RichEdit 默认处理插进了显示区——
  屏上有字（幻影文本）但串口没发出；退格/回车走 KEYDOWN 正常发出，但板子那行是空的，
  所以退格只回 BEL、回车只出新提示符。
- 修复（serial_gui.cpp ViewProc）：
  1. `WM_IME_CHAR` 与 `WM_CHAR` 共用处理（termTypeChar）；
  2. `WM_IME_COMPOSITION(GCS_RESULTSTR)`：让 RichEdit 上屏后把插入的文本转发串口并从本地删掉，
     同时用 `g_imeSwallow` 计数吞掉随后重复的 `WM_IME_CHAR`。
- 验证：用 ctypes 向 RichEdit 投递 `WM_IME_CHAR('l')/('s')` + KEYDOWN 回车，
  日志显示 TX l/s/CR，板子执行 ls 输出 driver/mnt/shell，界面渲染正确；退格（0x7F，
  板子回 08 20 08，本地同步删除）也通过。
- 构建：本机无 mingw，下载了便携版 w64devkit（GCC 16.2.0）到 `D:\AI\.tools\w64devkit\w64devkit\bin`。
  编译命令：`g++ -std=c++17 -O2 -static -static-libgcc -static-libstdc++ -municode -mwindows
  -o serial_gui.exe serial_gui.cpp -lws2_32 -lcomctl32 -lcomdlg32 -lgdi32`
  （工具链保留，以后可直接重编；调试辅助脚本已删，需要时可重写：ctypes PostMessage WM_KEYDOWN/
  WM_IME_CHAR 注入 + PrintWindow 截图即可做端到端验证）

## 功能：串口显示/发送编码可配置（自动 / UTF-8 / 文本 ANSI-GBK）
- 状态：`g_rxEnc` 0=自动 1=UTF-8 2=GBK(ANSI)，存 `serialmate.ini` 的 `enc=`；
  `rxDecode()` 解码 RX+日志，`txEncode()` 编码要发下去的本地字符（含退格按实际字节数回退）。
- 本轮新增：底部快捷按钮下方加"编码:"下拉框（`IDC_ENC`/`IDC_ENCLAB`），
  与 视图→串口编码 菜单共用入口 `applyEnc()`（写 ini、同步菜单勾选+下拉框、刷状态栏、
  重画未提交的当前行、输出提示）。菜单项文案统一为 自动（UTF-8 优先，失败退 GBK）/ UTF-8 / 文本 ANSI (GBK)。
- 实测：enc=1(UTF-8) 时板子 `printf '\326\320\316\304\n'`（GBK 字节）显示为乱码；
  enc=2 时同一条命令显示"中文"。IME 注入 中 后退格：UTF-8 发 3 个 0x7F、GBK 发 2 个，与记录一致。
- 注意：本机用后台方式（Bash `&` / PowerShell Start-Process）启动的 GUI 会随任务结束被杀，
  验证要在同一个工具调用里完成；程序交付给用户时由用户自己双击运行。

- 背景：用户报「SSH 连 192.168.0.110 连不上，MobaXterm 能连」。原 SSH 只是占位——对话框仅保存参数，
  根本没有连接通道。本轮从零补上：**不依赖 libssh/PuTTY/plink**，纯 Win32 + Winsock + CNG 自实现。
- 新增文件：
  - `ssh.h/.cpp`（~900 行）：版本交换 → KEXINIT 协商 → `curve25519-sha256` 密钥交换 →
    `aes128-ctr` + `hmac-sha2-256[ -etm@openssh.com]` → `password`/`keyboard-interactive` 认证 →
    session 通道 + `pty-req` + `shell`，之后 `loop()` 线程收发包，`window-change` 跟随终端尺寸。
    密码学自写：SHA-256、HMAC-SHA256、TweetNaCl 风格 X25519（gf[16] 梯形阶梯）；
    AES-128-CTR 走 CNG(bcrypt) 开 ECB 逐块生成密钥流（BCRYPT_CHAIN_MODE_ECB 实测不生效，
    ECB 下用 CBC 调用即可，等价）。
  - `term.h/.cpp`（~1100 行）：自绘 VT100/xterm 控件（类名 `SerialMateTerm`）：
    CSI/OSC 解析、光标定位、滚屏区、alternate screen、SGR 16/256/真彩、UTF-8 + CJK 双宽、
    回滚缓冲、双缓冲绘制（消除闪烁）、鼠标框选复制（Ctrl+Shift+C/V）、方向键/F1-F12、
    Shift+PgUp/PgDn 翻历史、`onResize` 回调。配色 One Dark 风（fg 0xD8DEE9 / bg 0x1B1E24）。
- 接入 `serial_gui.cpp`：Session 增 `term/ssh/sshUser/sshPass/sshInfo`；`startSsh/stopSsh`；
  新消息 `WM_APP_SSH_DATA/LOG/END`(WM_APP+6/7/8) 跨线程投递；layout() 里 SSH 会话用 Terminal
  占原 RichEdit 区域并隐藏 g_hView；状态栏 SSH 分支「已连接 xzs@host:22 | 会话 N | RX/TX | 端口 C x R」；
  左侧栏右键对 SSH 隐藏波特率、改为「断开 SSH / 重新连接」；ini 增 `sshpass=` `conntype=`。
- **SSH 规范踩坑（三个，全部靠 paramiko 本地服务端逐字节对比定位）**：
  1. 密钥派生哈希输入是 `string(mpint K) + H + char(x) + session_id`，**K 必须带 4 字节长度前缀**
     （H 的哈希里加了、派生时忘了当裸 32B 用 → 服务器报 `Corrupted MAC on input`）；
  2. **NEWKEYS 后 packet sequence number 不重置**（RFC 4253 §6.4）。我原先归零 → 报
     `Mismatched MAC`。删掉 `seqOut=seqIn=0` 即好；
  3. ETM 模式（`*-etm@openssh.com`）下 **length 字段不参与块对齐**，填充计算 `base=1` 而非 5，
     否则服务器 `padding error: need 28 block 16`。
  另：算法协商要用「客户端列表顺序优先取交集」，别反过来拿服务器列表当已选。
- 其它坑：GUI 里 SSH 报「地址解析失败」——原来只在串口路径 `WSAStartup`，SSH 路径要补；
  终端行列错乱（状态栏 34x25 但实际 67x25）——`WM_PAINT` 内按真实客户区自愈 `resizeGrid`。
- **构建命令（库要全，缺一个就链接失败并删掉旧 exe）**：
  `g++ -std=c++17 -O2 -static -static-libgcc -static-libstdc++ -municode -mwindows
  -o bin/serial_gui.exe serial_gui.cpp ssh.cpp term.cpp
  -lws2_32 -lcomctl32 -lcomdlg32 -lgdi32 -lshell32 -lole32 -luuid -limm32 -lbcrypt`
  （`-limm32` 来自 IME 那段，`-lbcrypt` 来自 AES/随机数，`-lole32 -luuid` 来自 TSF 接口。）
